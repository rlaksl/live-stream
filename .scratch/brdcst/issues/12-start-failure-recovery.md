# 송출 실패 복구·중복 시작 차단

Status: done
출처: `../review-1118.md` 2절 (주장 확인 #3, #4)

## 문제

- `startBroadcast`가 DB를 먼저 `live`로 바꾼 뒤 LiveKit 연결·트랙 전송을 한다. 연결이 실패하면 방이 생기지 않아 웹훅도 오지 않고 `live`가 남는다. 같은 화면에서 다시 시도하면 409로 막힌다.
- 두 탭이 동시에 시작하면 `.eq("status","waiting")` 갱신이 0행이어도 에러가 아니라 둘 다 성공한다.

## 완료 조건

- [x] 갱신된 행이 없으면 409. 한 탭만 송출 단계로 넘어간다.
- [x] 연결·트랙 전송 실패 시 서버 액션으로 `live → waiting` 복구(소유자만, 방송 중일 때만) 후 방 연결 해제·장치 정리. 같은 화면에서 다시 시작할 수 있다.
- [x] 복구를 연결 해제보다 먼저 해서 웹훅이 방송을 `종료`로 만들지 않게 한다.
- [x] 권한 조건: 시작 취소는 종료와 같은 조건(소유자 + 방송 중)이라 기존 `assertCanEnd`와 그 테스트를 그대로 쓴다.
