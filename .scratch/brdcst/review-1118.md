# 제출 전 외부 검토 의견 (2026-11-18)

공모전 제출용이면 홈에서 바로 볼 영상 만들기 → 방송 시작·종료 안정화 → A/B 권한 검증으로 범위를 잡아. 코드 수정 순서는 아래가 좋아.

## 1. 홈을 열자마자 영상이 보이게

지금은 `방송 중` 탭이 기본이라 라이브가 0건이면 마스코트와 빈 목록만 보여. 홈을 대표 영상 1개 → 방송 중 목록 → 최근 다시보기 순서로 바꿔.

- 대표 영상: 라이브가 있으면 `LIVE · 시청하기`, 없으면 실제 BRDCST에서 녹화한 영상에 `다시보기 재생`. 옆에 내 방송 시작 버튼을 둬. 비로그인 사용자는 로그인 후 방송 만들기로 바로 보내.
- 다시보기 두 장: `PC 화면·소리·마이크 송출`과 `휴대폰 카메라·마이크 송출`. 픽셀 TV 대신 각 녹화의 실제 프레임을 썸네일로 써. 검정·주황과 픽셀 TV는 로고와 빈 상태에 남겨도 브랜드가 살아.
- 모바일: 대표 영상과 두 버튼이 먼저 보이고, 그 아래 카드가 한 열로 이어지게 해.

중요한 건 시연용 녹화 두 개를 평가용 A/B와 다른 계정 소유로 만드는 거야. 그래야 누군가 A로 CRUD를 실습해도 홈에서 볼 영상이 사라지지 않아.

## 2. 방송 시작과 종료가 실제 송출 상태를 따라가게

현재 코드에서 가장 먼저 고칠 부분이야. DB는 먼저 `LIVE`가 되고, 그 뒤 LiveKit 연결과 영상·오디오 전송을 해. 연결 실패로 영상이 하나도 안 나가도 `LIVE`가 남을 수 있어.

- 시작 실패: 연결이나 트랙 전송이 실패하면 생성한 방과 장치를 정리하고, 서버에서도 실패한 시작을 복구해 같은 방송에서 다시 시도할 수 있게 해.
- 중복 시작: 같은 방송을 두 탭에서 시작하면 서버 갱신에 성공한 한 탭만 다음 단계로 보내. 기존 코드에서는 두 요청 모두 성공 응답을 받을 수 있었어.
- 종료: 종료 버튼, 브라우저의 공유 중지, 송출 탭 닫기를 각각 확인해. 세 경우 모두 시청 화면이 종료로 바뀌고, 홈의 LIVE 목록에서 빠지고, 새로고침 후에도 그 상태가 유지돼야 해.
- 송출 전 안내: `화면/카메라`, `마이크`, `공유 소리`를 각각 표시해. PC에서 공유 소리가 감지되지 않으면 방송자가 시작 전에 알아차릴 수 있게 해.

## 3. 인증은 화면 두 곳과 서버 검증만 손봐

- 평가용 로그인: A/B 버튼을 누르면 `로그인 중…`을 표시하고 실패하면 이유를 보여줘. 지금은 실패 응답이 화면에 표시되지 않아.
- 로그인 후 복귀: 방송 만들기나 시청 화면으로 돌아가는 주소는 같은 사이트 내부 경로만 허용해.
- 권한 시연: A가 만든 존재하는 방송을 B로 열어 시청하고, B의 수정·삭제·종료·송출 토큰 요청은 서버에서 거부되는지 확인해. 마지막으로 A가 다시 조회해 제목과 상태가 그대로인지 보면 돼.

## 축소 범위

시간이 모자라면 `송출 실패 복구·중복 시작 차단 → 실제 다시보기 두 장과 홈 버튼 → A/B 검증`까지만 해.

## 제출 직전 확인

심사위원처럼 로그아웃한 브라우저로 홈을 열어 바로 영상을 재생하고, 별도 기기 두 대로 PC 탭 소리와 전체 화면 시스템 소리를 각각 마이크와 함께, 모바일은 카메라와 마이크를 함께 받아봐.
